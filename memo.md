# Памятка по архитектурным изменениям (Memo)

## Описание задачи
В проекте происходит важное архитектурное изменение, направленное на перенос части логики на клиентскую сторону, с сохранением серверного управления этой логикой.

*   **Backend:** Теперь Backend должен отдавать не просто статические JSON-схемы для отрисовки компонентов, но и встраивать в эти JSON сложные логические правила (например, в виде строк, содержащих JavaScript-код или сложный DSL). Это позволит динамически управлять поведением формы с сервера.
*   **Frontend:** Angular-приложение получает эту JSON-схему с внедренной логикой. Его задача — распарсить эту логику и на её основе динамически строить сложные объекты, управлять видимостью полей, валидацией и другими взаимодействиями, выполняя полученные правила на клиенте.
*   **Agent (LLM + SSR):** Поскольку агент общается с приложением не через полноценный браузер, а через SSR (Server-Side Rendering) и парсинг HTML/JSON, он не исполняет JavaScript автоматически. Поэтому агенту необходимо "научиться" извлекать эту фронтовую логику (из HTML или JSON-схем, если они внедрены в страницу) и инструктировать LLM анализировать её. LLM должна имитировать поведение клиента (например, понимать, что поле стало обязательным или скрытым из-за определенного значения другого поля) без реального выполнения JS в браузере.
